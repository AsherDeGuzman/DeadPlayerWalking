## Known issues and remaining validation

- The full smoke test passed in Godot 4.7.1 after the grave-bound echo and animated transition changes. Earlier smoke runs have intermittently reported ObjectDB instances leaked at exit; this is a harness-cleanup warning and has not accompanied failed assertions in successful runs.
- No source `.wav`, `.ogg`, or `.mp3` files are supplied. `AudioManager` intentionally uses generated fallback music and sound cues.
- Viewport sizing and touch input are exercised headlessly at four landscape or near-square sizes. The title and gameplay have been visually checked in a 1280 × 720 desktop window, but not on a physical phone or tablet. A release candidate still needs a hands-on touch/UI check on target hardware.
- No Android export build or device performance/thermal benchmark has been run. Headless results do not establish frame-rate performance on low-end mobile hardware.
- Room encounters place the skeleton, aggressive creature, and ranged archer deterministically using resource-configured stats; verify their balance, the enlarged PreviousSelf art/movement animation, and the player's crossbow reload indicator with extended hands-on play.
- Projectile/effect pooling has not been added: current attack and effect rates are bounded, and no device profiling has shown a need for pooling.
- On this Windows setup, the Godot editor has intermittently exited with code `-1073741819` after asset import. A fresh import and separate runtime smoke test have subsequently completed successfully; verify both steps if the editor exit recurs.
